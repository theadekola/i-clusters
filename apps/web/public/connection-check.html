Certificate warning or network failure

A browser request failure cannot distinguish an untrusted certificate from a routing or firewall problem. Open the direct health check to see the browser's own error. Do not bypass certificate verification.

For Caddy LAN HTTPS, run on the Ubuntu controller:

sudo iclusters certificate > iclusters-root.crt
openssl x509 -in iclusters-root.crt -noout -fingerprint -sha256

Transfer only that public certificate through a trusted channel. Compare its SHA-256 fingerprint before installing it. Never distribute a private key.

iPhone/iPad: install the certificate profile in Settings → General → VPN & Device Management. Then enable it under General → About → Certificate Trust Settings. Android: install it as a CA certificate. Windows: import into Trusted Root Certification Authorities. Firefox may require its own Authorities import.

Trust survives routine renewal while the same root CA and certificate storage are retained. A public domain with automated DNS validation is another option; it does not require publishing the dashboard.

Already using MikroTik or another VPN?

Keep your existing VPN. You do not need to create an i-Clusters WireGuard gateway. Test with Wi-Fi off and the existing VPN connected. It must route to this installation's address and allow its HTTPS port, including the return traffic.

Old offline screen or stale browser version?

Close other i-Clusters tabs first. Reset browser recovery removes only this installation's root service worker. It preserves accounts, cookies, saved credentials and server records. The dashboard registers its current worker when it opens again.
