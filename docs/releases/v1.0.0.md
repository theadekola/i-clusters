The [application and installer check run](https://github.com/theadekola/i-clusters/actions/runs/42959774625) passed API and web tests, Chromium layout checks at desktop and mobile sizes, deployment startup, Docker worker recovery, encrypted controller restore and dependency and runtime image scans. ## Included functionality

- A responsive infrastructure dashboard, monitoring, measured alert rules, activity history and configured external notifications.
- Proxmox VE inventory and supported VM/CT creation, lifecycle, storage, network, backup, restore and task workflows, with role checks and action approvals.
- Paired Linux Docker hosts and Proxmox node connectors, supported container/image/network/volume management, image update checks and recoverable replacement workflows.
- TrueNAS pool, disk, dataset, snapshot and share integrations, with version-dependent API compatibility.
- Verified SSH access, multi-tab terminals and SFTP; automatic connector setup with separate SSH and required guest-restart popups.
- Owner-selected OpenAI, Claude, Gemini, DeepSeek, Groq or Mistral configuration, matching model choices and read-only AI assistance.
- MFA, recovery codes, revocable sessions, encrypted integration configuration, controller backup/restore and upgrade rollback tooling.

## Release changes

- Consistent page paths, tab headings, mobile layouts and visible pending/refresh indicators.
- Software update review and installation in a popup, with progress and reconnection feedback.
- SSH host-key checks, Docker host discovery and a direct Connect TrueNAS action.
- Storage inventory excludes registrations assigned only to other nodes while retaining applicable offline storage.
- The Caddy build includes patched go-jose and x/net dependencies. CI verifies the running binary's dependencies and scans runtime images.

## Installation and upgrades

Follow the [installation guide](../../README.md) and [deployment instructions](../../PRODUCTION.md). Tracking-branch installations use `sudo iclusters update`. For a repeatable installation, select an existing Git tag or commit and record the source revision. Preserve encryption keys, keep an encrypted off-host backup and finish or recover active operations before upgrading.

## Deployment scope

Run one controller per installation. Record local provider and guest versions, restore results and device checks using the [compatibility guide](../compatibility.md) and [installation checklist](../acceptance-checklist.md). The [security policy](../../SECURITY.md), [controller privacy document](../../PRIVACY.md) and [self-hosted terms](../../TERMS.md) explain operational responsibilities.
